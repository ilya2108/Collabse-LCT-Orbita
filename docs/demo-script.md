Статус: черновик (8 октября). Финальная сверка — после пересева демо-данных 10 октября,
смоук-прогон по этому файлу — утром 11 октября. Пароли демо-аккаунтов и basic-auth
«Почты стенда» — только в README стенда из пакета сдачи, не в этом файле (файл публичный).

Контекст: по итогам Q&A организаторов (06.10, пересказ своими словами) жюри должно иметь
возможность самостоятельно пройти тест; полная регистрация не обязательна — подходят
демо-аккаунты и экспресс-режим на 3–5 минут. Раздел 1 построен ровно под это требование.

## 1. Экспресс-сценарий «жюри за 5 минут»

Сквозной цикл «тест → категория → подборка → приглашение» на двух демо-аккаунтах,
без регистрации. Все шаги — в интерфейсе, API не требуется.

### 1.1. Кандидат: вход → экспресс-тест → категория и граф (≈ 3 минуты)

1. Войти как `judge-candidate@fsp.local` (пароль — README стенда). Опрос уже заполнен
   (бэкенд, middle), согласие дано — жюри попадает сразу на главную кабинета.
2. Нажать «Пройти тест». На стенде включён демо-режим (`TEST_DEMO_MODE=1`), на экране
   старта это видно по переключателю «Демо-режим» и пояснению.
3. Экспресс-тест: 3–5 заданий по демо-профилю грейда (для middle — 4), 5–8 минут
   при вдумчивом прохождении, быстрее — при беглом. Таймер задания мягкий: истечение
   времени не сбрасывает ответ, а только помечает его. Ответы автосохраняются —
   обновление страницы ничего не теряет.
4. Экран результата: присвоенная категория (например, «Бэкенд · Middle») с бейджем
   «категория присвоена в демо-режиме», граф навыков с активными узлами, уровень Q.
5. Что ещё показать здесь: повторный тест доступен не через 90 дней, а через
   `DEMO_COOLDOWN_SECONDS` (на стенде 60 секунд) — жюри может тут же пройти тест
   на другой грейд.

### 1.2. Работодатель: потребность → подборка → приглашение → пайплайн (≈ 2,5 минуты)

1. Войти как `judge-employer@fsp.local` (другой браузер или окно в режиме инкогнито,
   чтобы не разлогинивать кандидата).
2. Открыть готовую потребность: текст, зарплата «от–до», редактируемый подграф узлов.
3. Нажать «Обновить подборку»: в новой версии появляется только что протестированный
   `judge-candidate` (категория свежая). У каждой строки — «Почему здесь»: закрытые
   узлы, сила и свежесть подтверждений, вклад достижений ФСП.
4. **Обратите внимание на бейдж целостности** (30 секунд): у только что протестированного
   кандидата — «целостность: высокая». Это индекс поведенческих сигналов сессии (крупные
   вставки, уходы со вкладки, слишком быстрые ответы, ответ без набора): high — ни одного
   флага, medium — 1–2, low — 3+. Проговорить позицию: это флаги, а не вердикты —
   использование ИИ считаем нормой, работодатель получает прозрачность процесса и повод
   для вопроса на собеседовании; тексты ответов не собираются (только длины и тайминги),
   кандидат предупреждён баннером до старта. Детали — `02-testing.md` §11.
5. Открыть карточку кандидата (псевдоним, без контактов) → «Пригласить»: название,
   зарплата «от–до» (обязательна), отправить.
6. Показать пайплайн найма по потребности: приглашение появилось в колонке «Отправлено»,
   видны стадии и история переходов.

### 1.3. Замкнуть цикл (опционально, +1 минута)

Вернуться в окно кандидата: входящее приглашение с зарплатой и объяснением «почему
именно вы» → «Принять» → контакты раскрыты у обеих сторон; у работодателя приглашение
переходит в «Принято», стадию в пайплайне можно перевести дальше (например, «Интервью»).

### 1.4. Роль параметров демо-режима

| Параметр | Дефолт | Роль |
|---|---|---|
| `TEST_DEMO_MODE` | `false` (на стенде `1`) | включает экспресс-тест: демо-профили грейда — связный подграф меньшего размера, без вторых заданий на пограничных узлах и без персонального сценария; подробности и обоснование честности — `02-testing.md` §4.1 |
| `DEMO_COOLDOWN_SECONDS` | `300` (на стенде `60`) | заменяет кулдаун смены грейда `GRADE_COOLDOWN_DAYS=90` на секунды, чтобы жюри увидело повторный тест за минуты, а не через 90 дней |

В проде оба параметра выключены; результат демо-сессии всюду помечен `demo`
(бейдж в карточке, запись в истории категории).

## 2. Полное демо: 10–12 минут (сценарий видео)

Хронометраж под запись; для живого показа те же блоки, темп свободный.

| Время | Блок | Что показываем |
|---|---|---|
| 0:00–1:00 | Регистрация | новый кандидат адресом `*@fsp.local` → письмо в «Почте стенда» → подтверждение → выбор роли → согласие (версия политики) |
| 1:00–2:30 | Профиль | опрос (бэкенд, middle), одно свершение, привязка ФСП ID (заглушка реестра), импорт достижений |
| 2:30–5:00 | Экспресс-тест | 4 задания: автосохранение, мягкий таймер, асинхронная проверка открытого ответа («Проверяем ответы…»); результат: граф, Q, категория с бейджем «демо-режим» |
| 5:00–6:30 | Потребность | работодатель: текст потребности + зарплата → разбор в подграф, правка чипов (узел/уровень/важность), «Какие задания проверят это», экран рекомендованных категорий |
| 6:30–8:00 | Подборка | версия подборки, «Почему здесь»; бейдж целостности у протестированного кандидата (флаги, не вердикты); кандидат с ФСП выше близнеца без ФСП; уточнение фильтров → новая версия с диффом («было 14 → стало 9») и закреплёнными кандидатами; кандидат без теста — со статусом «грейд не подтверждён» внизу выдачи |
| 8:00–9:00 | Приглашение | карточка без контактов → приглашение с зарплатой «от–до»; предупреждение «ниже ожиданий кандидата» без раскрытия суммы |
| 9:00–10:00 | Контакт и пайплайн | кандидат: «почему именно вы» → принятие → контакты у обеих сторон; работодатель: стадии пайплайна, перевод «Принято» → «Интервью», история переходов |
| 10:00–12:00 | Дополнительно | отклик на вакансию (контакты раскрываются по самому отклику); «Задание недели»; повторный тест через минуту (`DEMO_COOLDOWN_SECONDS`); телеграм-бот: уведомление о приглашении и недельный дайджест по ручному запуску; удаление аккаунта |

Блоки последней строки показываем только если работают на стенде — состав фиксируется
на синке 10 октября; что не вошло в сдачу, честно отмечено в `roadmap.md`.

## 3. Чек-лист «перед показом»

Прогоняется перед записью видео и утром 11 октября (смоук).

- [ ] Пересев демо-данных: `make demo` (под капотом `POST /internal/demo/reset`) —
      идемпотентно, старые прогоны жюри удаляются.
- [ ] `judge-candidate@fsp.local` — без категории, опрос заполнен, согласие дано
      (экспресс-тест стартует с первого клика).
- [ ] `judge-employer@fsp.local` — потребность с подграфом, хотя бы одна версия подборки,
      приглашения в разных статусах (дашборд не пустой).
- [ ] Дашборды непустые: у демо-кандидатов категории, входящие приглашения и «Задание
      недели» (одно отвечено и оценено); у демо-компании — ответы с баллами.
- [ ] «Почта стенда» (Mailpit) открывается за basic-auth, письмо о регистрации доходит.
- [ ] `TEST_DEMO_MODE=1`, `DEMO_COOLDOWN_SECONDS=60`; лимиты LLM не исчерпаны
      (`GET /internal/llm/usage`), эвристический фолбэк включён.
- [ ] Телеграм-бот: токен задан (или осознанно стаб-режим — тогда блок бота из демо
      убираем); ручной запуск дайджеста отрабатывает.
- [ ] `GET /health/ready` зелёный, Swagger открывается, сквозной прогон раздела 1
      пройден руками от начала до конца.
- [ ] Пароли демо-аккаунтов и basic-auth — в README стенда пакета сдачи; в репозитории
      и этом файле их нет.

## 4. Проверка на своих парах «вакансия — резюме»

Для проверки жюри на собственном наборе пар:

- **Честный путь** — `make import-pairs FILE=pairs.jsonl --mode bulk`: каждое резюме
  превращается в кандидата с сид-сессией, категория присваивается по правилам платформы,
  дальше работает обычная подборка и приглашения.
- **Ориентир по резюме** — `--mode unverified`: ранжирование по заявленным в резюме
  навыкам на служебной странице, без категорий и без возможности пригласить. Это
  инструмент проверки, не продуктовая выдача.

Формат файла — JSONL, по паре на строку: `{"vacancy_text": "…", "resume_text": "…",
"label": "…"}` (label необязателен). Отчёт по итогам: «обработано N из M пар (полные,
preview), пропущено K, причины» — видно, какая часть набора покрыта и почему (например,
специализация вне MVP). Подробности изоляции режимов — `03-matching.md` и `compliance.md`.

## 5. Если стенд недоступен

1. Демо-видео из пакета сдачи (раздел 2) — полный сквозной сценарий.
2. Локальный запуск по [`08-run.md`](08-run.md): `make dev`, сид, `LLM_PROVIDER=replay`
   (записанные ответы LLM — работает без ключей и сети до провайдера); демо-аккаунты
   и экспресс-режим доступны так же, как на стенде.
