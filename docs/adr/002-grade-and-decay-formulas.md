# ADR-002. Формулы силы узла, затухания, уровня Q и грейда

- Дата: 6 октября 2026
- Статус: принято (параметры могут уточняться по ярусу A валидации 8 октября — в YAML, не в коде)
- Участники: A, C

## Контекст

Профиль кандидата — граф навыков, где каждый узел подтверждается несколькими свидетельствами
разных источников (тест, достижение ФСП, регулярное задание) с разными датами. Нужны правила,
которые (а) объединяют несколько подтверждений в одну силу узла, (б) учитывают устаревание,
(в) выводят уровень и грейд из структуры графа, а не из самоописания, и (г) просты настолько,
чтобы объяснить их жюри на одном слайде и покрыть юнит-тестами. Методологическая основа —
«Квантовая модель компетенций» К. Кичинского (2023): три слоя, уровень как связность, угасание
неиспользуемых навыков. Формулы ниже — наша конкретизация этих идей.

## Решение

### 1. Затухание: экспоненциальный полураспад

Вес подтверждения `e` в момент `t`: `w_e(t) = w0_e · 2^(−(t − t_e) / τ_e)`,
где `τ = τ_source × k_layer` (`τ_test = 240`, `τ_fsp = 365`, `τ_regular = 120` дней;
`k_D = 1.5`, `k_B = 1.0`, `k_C = 0.75`).

Почему так: полураспад интуитивно объясним («через 8 месяцев результат теста стоит вдвое
меньше»), монотонен, не обнуляется скачком и даёт один параметр на источник и один множитель
на слой. Линейное затухание обнуляет резко и требует отдельной «даты смерти»; ступенчатое —
даёт скачки в рейтинге в день перехода. Слой влияет на скорость: фундамент (D) забывается
медленнее, инструменты контекста (C) устаревают быстрее.

### 2. Сила узла: noisy-OR

`S_v(L, t) = 1 − Π_e (1 − w_e(t))` по подтверждениям узла с уровнем ≥ L; узел активен на
уровне L при `S_v ≥ 0.5`.

Почему так: подтверждения — независимые свидетельства, и noisy-OR отражает ровно это: несколько
слабых усиливают друг друга, одно сильное почти насыщает узел, результат всегда в [0, 1].
Сумма весов выходила бы за 1 и требовала обрезки; максимум веса игнорировал бы «реанимацию
усилием» (старый тест 0.45 + свежее задание 0.3 → 0.615, узел активен, тогда как `max` дал бы
0.45 — не активен); среднее штрафовало бы за слабые дополнительные подтверждения.

### 3. Свежесть: максимум текущего веса

`w_now = max_e w_e(t)`: «свежо» ≥ 0.8, «тускнеет» 0.5–0.8, «погасло» < 0.5. Это показатель
для интерфейса и компонент `freshness` в ранжировании; он намеренно отделён от силы, чтобы
кандидат видел, какое именно подтверждение пора обновить.

### 4. Уровень Q: размер остовного леса

`Q = |A| − C(A)` по активным узлам `A` и числу компонент связности порождённого подграфа.

Почему так: это минимальное число рёбер, связывающих активные узлы, — прямое выражение идеи
«уровень = связность, а не количество». Считается за линейное время (DFS/union-find), не зависит
от порядка обхода, легко проверяется на примерах (цепочка из 4 → 3; две пары → 2). Альтернативы
(число рёбер в подграфе, плотность) поощряли бы циклы и сравнивали бы специализации с разной
плотностью графа нечестно.

### 5. Грейд: профиль с целевым подграфом и структурными условиями

Грейд считается по подтверждениям **текущей тестовой сессии** на целевом подграфе `T` профиля:
доля активных узлов, `Q_T`, структурные условия (middle — хотя бы один узел вне слоя B;
senior — хотя бы по одному узлу D и C, «ходок»). Затухание и достижения ФСП на ярлык грейда
не влияют — они меняют силу профиля и позицию в рейтинге.

Почему так: категория по требованиям задачи присваивается только по опросу и тесту; если бы
затухание меняло ярлык, кандидат терял бы грейд без всякого действия, а приглашения с
зафиксированным грейдом становились бы противоречивыми. Структурные условия вместо одного
порога отражают разницу грейдов по форме графа, а не по числу правильных ответов.
Пороги (3/4, 5/7, 7/10; `Q_T` 2/4/6) выбраны так, чтобы один провальный узел не ронял грейд,
а два несвязанных «островка» — не давали его. Демо-профили повторяют те же структурные
условия на меньшем подграфе.

### 6. Ранжирование: аддитивная формула

`score = 0.45·coverage + 0.20·strength + 0.15·fsp + 0.10·freshness + 0.10·connectivity`.
Аддитивность гарантирует, что кандидат без ФСП не штрафуется (компонент просто 0), а каждый
вклад объясним по отдельности в карточке «Почему здесь». Веса — отдельное решение
(`docs/03-matching.md`), абляции — ярус F валидации.

## Альтернативы, которые отклонили

| Вариант | Почему нет |
|---|---|
| IRT / байесовская сеть по узлам | нет данных для калибровки до хакатона; необъяснимо жюри за минуту; IRT-подобная логика используется только в валидации для персон |
| Эмбеддинги навыков и косинусная близость | непрозрачно, не воспроизводимо, спорно для категоризации; подбор на графе детерминирован |
| Грейд как простая сумма баллов | не отличает «много разрозненного» от «связного ядра», противоречит основе модели |
| Затухание влияет на грейд | ярлык «протухает» без действий кандидата; ломает снимки приглашений |
