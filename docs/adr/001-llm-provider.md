# ADR-001. Провайдер LLM: GigaChat основной, YandexGPT резерв, режимы без ключа

- Дата: 6 октября 2026
- Статус: **принято, ждёт smoke-теста** (строгий JSON на `need_parse` и `variant_judge`,
  20 вызовов; по результату подтверждаем выбор или меняем местами основной и резерв)
- Участники: A (решение), все (обсуждение)

## Контекст

LLM нужна в четырёх местах: разбор потребности в подграф (`need_parse`), генерация вариантов
заданий из шаблонов (`variant_generate`) и их судейство (`variant_judge`), оценка открытых
ответов по рубрике (`answer_grade`), плюс вспомогательные промпты (персональные сценарии,
разбор резюме, банк ответов для валидации). Объём за хакатон — порядка 8–10 млн токенов, пик —
генерация пула вариантов 7–8 октября. Требования: структурированный JSON-вывод по Pydantic-схеме,
российский провайдер (данные кандидатов, хоть и без ПДн, не должны уходить за периметр РФ
без нужды), работоспособность решения у жюри **без ключей**, предсказуемая стоимость.

## Решение

1. **Основной провайдер — GigaChat** (API Сбера): `GigaChat-2-Pro` для судьи, грейдера и разбора
   потребности (точность важнее цены), `GigaChat-2-Lite` для генерации вариантов (объём важнее).
   SDK `gigachat`. Точные идентификаторы моделей и тарифы проверяются в кабинете 6 октября;
   имена моделей — в конфигурации (`GIGACHAT_MODEL_STRONG`, `GIGACHAT_MODEL_FAST`), не в коде.
2. **Резерв — YandexGPT** (Yandex AI Studio, SDK `yandex-cloud-ml-sdk`, модель `YANDEX_MODEL`)
   за той же абстракцией `LLMProvider.complete_json(prompt_name, variables, schema, temperature)`.
   Переключение — одной переменной `LLM_PROVIDER`; автоматический фолбэк после исчерпания
   повторов у основного.
3. **Режимы без ключа** (обязательны, решение жюри запускается без секретов):
   - `replay` — кэш ответов `backend/seed/llm_cache.jsonl`, собранный `make llm-freeze` из
     журнала `llm_call`; даёт работающий разбор потребности и грейдинг демо-ответов;
   - `rules` — детерминированный словарь «ключевое слово → узел» (`skills/keywords.yaml`)
     для разбора потребности и резюме;
   - `stub` — фикстуры для CI и эвристический грейдинг по ключевым словам рубрики
     с пометкой «режим без LLM». **Дефолт** в `.env.example` и в тестах.
4. **Надёжность вывода**: системная инструкция «только JSON по схеме», структурированный вывод
   провайдера там, где он есть (у GigaChat — в бете, это и проверяет smoke-тест), вырезание
   ограждений, валидация Pydantic, до 2 повторов с текстом ошибки, затем фолбэк на резерв,
   затем `rules`/`stub`. Семафор 4 параллельных вызова (`LLM_MAX_CONCURRENCY`), таймаут 60 с.
5. **Учёт и предохранители**: каждый вызов — строка `llm_call` (вид, провайдер, модель, версия
   и хэш промпта, токены, задержка, оценка стоимости, статус `ok|error|cached|fallback`,
   запрос и ответ без ПДн); кэш по `sha256(kind + prompt_version + model + вход)`;
   `LLM_DAILY_TOKEN_CAP` останавливает фоновые джобы и даёт понятную ошибку 503 вместо тихого
   расхода; открытые ответы при исчерпании капы не теряются.
6. **Без ПДн в промптах**: `sanitize_for_llm()` перед каждым вызовом, идентификаторы — UUID,
   текст ТЗ в промпты не попадает.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Только YandexGPT | у команды нет подтверждённой квоты; структурированный вывод тоже с оговорками; остаётся резервом |
| Зарубежные API (OpenAI, Anthropic) | периметр данных и оплата из РФ; для хакатона с ФСП неуместно |
| Локальная модель (Ollama) | качество судейства и грейдинга недостаточно для аргумента «судье можно верить»; нет ресурсов на стенде 4 ГБ |
| Без LLM вообще (только правила) | теряем уникальность вариантов и оценку открытых ответов — ядро механики тестирования |

## Последствия

- Плюсы: один интерфейс, замена провайдера без правок кода модулей; жюри запускает без ключей;
  расходы видны в `GET /internal/llm/usage`.
- Минусы: два SDK в зависимостях; бета структурированного вывода может потребовать
  «ручного» парсинга; стоимость зависит от тарифа, который уточняется 6 октября.
- Что проверяет smoke-тест (W3, `python -m app.tools.llm_smoke`): доля валидного JSON
  с первой попытки ≥ 90 %, p95 задержки ≤ 15 с, отсутствие ограждений в ответе при
  структурированном режиме. При провале — YandexGPT становится основным, GigaChat резервом,
  статус ADR меняется на «принято с изменением».
- Связанные документы: `docs/02-testing.md` §3, §5; `docs/security-152fz.md` §6;
  `backend/app/modules/llm/`.
