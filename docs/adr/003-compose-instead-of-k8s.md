# ADR-003. Docker Compose вместо Kubernetes для стенда и проверки жюри

- Дата: 6 октября 2026
- Статус: принято
- Участники: A (решение), все (обсуждение)

## Контекст

У команды есть готовые k8s-манифесты и опыт k3s-стенда из «Альмы» (ЛЦТ 2026). Требования
задачи к развёртыванию: контейнеризация желательна, запуск по инструкции обязателен. Сроки —
шесть дней, стенд нужен с 7 октября, проверять решение будут эксперты на своих машинах
и на нашем стенде. Ресурсы — VPS на 4 ГБ памяти.

## Решение

Развёртывание — **`docker compose` v2** с профилями:

- `dev` (локально): postgres, keycloak (realm `fsp` импортируется при старте), mailpit, backend;
  frontend — vite на хосте с прокси `/api`;
- `full` (локально, для проверки жюри): то же + frontend в контейнере (nginx :3000) +
  `fsp-registry-stub` + `scheduler`;
- `prod` (VPS): всё из `full` + Caddy (авто-TLS, хосты `*.nip.io`), Mailpit как «Почта стенда»
  за basic-auth, `restart: always`, healthchecks, лимиты памяти, swap.

Инструменты: `Makefile` (`make dev`, `make seed`, `make demo`, `make vm-deploy`,
`make vm-smoke`), один `.env.example` с плейсхолдерами, ожидание миграций через
`python -m app.tools.check_migrations`, сид идемпотентный. Kubernetes-манифесты «Альмы»
не переносим; описываем как путь развития (`docs/09-beyond-mvp.md` §6).

## Почему не Kubernetes

| Аргумент | Пояснение |
|---|---|
| Время | k3s + ingress + cert-manager + секреты + NetworkPolicy — минимум день A, которого нет: день 7 — механика теста, день 8 — сквозной сценарий |
| Проверка жюри | `docker compose up` на любой машине с Docker; k8s требует кластер или k3d — лишний барьер для эксперта |
| Ресурсы | Keycloak + PostgreSQL + backend + scheduler ≈ 2 ГБ; k3s с системными подами на 4 ГБ VPS оставляет меньше запаса |
| Нет потребности | один экземпляр backend (in-process rate-limit, семафор LLM, кэш), нет автоскейла, нет нескольких окружений |
| Риск | Keycloak — самый капризный компонент стенда; compose проще диагностировать и перезапускать в день гейта |

## Альтернативы

| Вариант | Почему нет |
|---|---|
| k3s на VPS (как в «Альме») | см. таблицу выше; манифесты есть, но адаптация realm, секретов и ingress под новый проект — день работы |
| Docker Swarm | ничего не добавляет к compose для одного хоста |
| Без контейнеров (systemd) | теряем воспроизводимость запуска у жюри |

## Последствия

- Плюсы: стенд поднимается 7 октября скриптом; жюри запускает локально по `docs/08-run.md`;
  одна конфигурация для dev / full / prod через профили и `.env`.
- Минусы и ограничения: один экземпляр backend — rate-limit, семафор LLM и кэш живут
  в процессе (описано в `docs/01-architecture.md` §9); нет zero-downtime деплоя (деплой —
  после вечернего синка, короткий простой допустим); масштабирование — через вынос общего
  состояния (roadmap).
- Безопасность стенда: секреты только в `.env` на VPS, Mailpit за basic-auth, сброс пароля
  отключён на стенде, письма удаляются через 24 часа (`docs/security-152fz.md` §8).
- Связанные документы: `deploy/`, `Makefile`, `docs/08-run.md`, `docs/09-beyond-mvp.md` §6.
