# Чек-лист требований (черновик трассировки)

Рабочий чек-лист для ежевечернего синка: требования задачи пересказаны своими словами
по плану команды (§2, §3.7, §5, §7.5, §11), текст ТЗ не цитируется. Статусы обновляются
каждый вечер; 10 октября таблица переезжает в `docs/compliance.md` с окончательными ссылками.

Статусы: `нет` — не начато; `в работе`; `есть` — работает локально; `стенд` — проверено
на стенде; `концепция` — описано в документации, в коде нет.

## 3. Правила данных и механик

| Требование (своими словами) | Где реализуем | Статус (6 окт) |
|---|---|---|
| Категория = специализация × грейд, только по опросу и тесту | `candidate_category` пишется только из `test_session` | нет |
| Самоописание не влияет на порядок в подборке | формула без заявленных полей, стек — только фильтр, тест абляций | нет |
| Достижения ФСП поднимают кандидата внутри категории | компонент `fsp` в `score` и `profile_score` | нет |
| Кандидат без ФСП не штрафуется | аддитивная формула, тест «не выпадает при равном покрытии» | нет |
| Устойчивость заданий к распространению | пул вариантов, лимит показов, персональные сценарии, цифры в `02-testing.md` §7 | нет |
| Стабильность грейда, дискриминативность, соответствие эталону | `make validate`, `validation-report.md` | нет |
| Модель компетенций с атрибуцией основы | `skills-model.md` §1, ADR-002 | есть (черновик) |
