# Соответствие требованиям: трассировка «требование → где реализовано»

Статус: draft (11 октября, день сдачи). Требования пересказаны своими словами (текст ТЗ
конфиденциален); источники: пересказ ТЗ и разъяснения организаторов в Q&A 06.10
([`drafts/qa-implications-2026-10-08.md`](drafts/qa-implications-2026-10-08.md)).
Рабочий чек-лист с историей статусов — [`drafts/compliance-checklist.md`](drafts/compliance-checklist.md).

## 1. Как читать

Статусы: **реализовано** — работает на стенде; **частично** — ядро работает, часть
сценария упрощена (что именно — в строке); **концепция** — описано в документации
и roadmap, в коде нет. «Как проверить» — шаг на стенде <https://orbita.185.239.51.92.nip.io>
(путь кликами — [`demo-script.md`](demo-script.md)) или эндпоинт в Swagger `/api/v1/docs`.

## 4. Правила данных

| Правило (пересказ) | Где реализовано | Как проверить | Статус |
|---|---|---|---|
| Категория = специализация × грейд, присваивается только сессией теста | `candidate_category` пишется только из `finish` сессии | `GET /candidates/me/category` до/после теста | реализовано |
| Самоописание не влияет на порядок в подборке | формула ранжирования без заявленных полей; стек — только фильтр | [`03-matching.md`](03-matching.md) | реализовано |
| Достижения ФСП — только ранжирование внутри категории, не грейд; кандидат без ФСП не штрафуется | аддитивный компонент `fsp` в формуле | [`03-matching.md`](03-matching.md), [`05-fsp-integration.md`](05-fsp-integration.md) | формула — реализовано; импорт данных ФСП — концепция |
| ПДн зашифрованы, в логи и LLM не попадают | `core/pii.py` (Fernet + blind index), `sanitize_for_llm()`, аудит доступа | [`security-152fz.md`](security-152fz.md) | реализовано |
| Телеметрия теста без текстов ответов — только длины и тайминги, с предупреждением | `assessment/integrity`, баннер перед тестом | [`02-testing.md`](02-testing.md) §11.3, §11.5 | реализовано |
| Контакты — только при согласии и основании (`contact_grant`) | единственный эндпоинт контактов + аудит | §2, §3 выше | реализовано |

## 7. Явные интерпретации спорных формулировок

- **«Вручную либо загрузка PDF»** — в MVP реализован ручной путь; разбор PDF описан
  и отложен (roadmap) — честнее показать один надёжный путь, чем два хрупких.
- **«Отрасль»** — трактуем как ИТ-направление; индустрия — наше расширение.
- **Контакты при отклике кандидата** — раскрываются в момент отклика с явным согласием.
- **Понижение грейда** при результате ниже порога — допустимая интерпретация;
  повышение — только отдельным тестом (после кулдауна с обоснованием).
- **Внешние API/LLM** — используются и явно задекларированы: GigaChat (резерв YandexGPT);
  что передаём — только обезличенные тексты заданий и ответов (`sanitize_for_llm`).
- **Кандидат без категории** — по рекомендации Q&A показывается со статусом
  «грейд не подтверждён» и понижением, а не скрывается полностью.
- **Preview-специализации** — граф без теста, помечены `preview`.

## 8. Что не вошло и почему

Осознанно не делаем (в т. ч. по позиции организаторов в Q&A): агрегация внешних вакансий,
ранжирование дисциплин ФСП, делёж вклада в командных результатах, прокторинг в MVP.
Полный список концепций с механикой — [`09-beyond-mvp.md`](09-beyond-mvp.md)
и [`roadmap.md`](roadmap.md).
